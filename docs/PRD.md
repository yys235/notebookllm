## 1. 产品概述

### 1.1 产品定位

NotebookLLM 是一个支持本地部署的**智能笔记系统**，融合了现代笔记应用的核心功能与 AI 能力。产品核心特点是**源文档锚定（Source-Grounded AI）**，所有 AI 回答都严格基于用户的笔记内容，极大降低 AI "幻觉"问题。

### 1.2 目标用户

| 用户群体 | 使用场景 |
|---------|---------|
| 知识工作者 | 日常笔记、会议记录、项目文档管理 |
| 研究人员/学生 | 学术笔记、论文阅读、知识整理 |
| 开发者 | 技术文档、代码笔记、API 文档 |
| 团队/企业 | 内部知识库、SOP 文档、协作共享 |

### 1.3 核心价值

- **智能检索**: 基于 RAG 的语义搜索，而非简单关键词匹配
- **知识沉淀**: 将碎片化信息转化为结构化知识
- **安全可控**: 支持本地部署，数据完全自主可控
- **灵活分享**: 多种分享方式，支持密码保护和过期设置

## 3. 用户故事

### 3.1 笔记管理

```
US-001: 创建新笔记
作为一名用户
我想要快速创建新笔记
以便于记录我的想法和信息

验收标准:
- 点击"新建笔记"按钮可创建空白笔记
- 自动跳转到编辑页面
- 支持输入标题和内容
```

```
US-002: 编辑笔记内容
作为一名用户
我想要使用富文本编辑器编辑笔记
以便于格式化我的内容

验收标准:
- 支持粗体、斜体、下划线等基础格式
- 支持标题、列表、代码块
- 支持插入图片和链接
- 编辑器响应流畅，无明显延迟
```

```
US-003: 搜索笔记
作为一名用户
我想要通过关键词搜索笔记
以便于快速找到需要的内容

验收标准:
- 搜索框实时响应
- 匹配标题和内容
- 高亮显示匹配结果
- 支持按时间/标题排序
```

### 3.2 分享功能

```
US-004: 分享笔记给他人
作为一名用户
我想要生成分享链接
以便于将笔记分享给其他人查看

验收标准:
- 一键生成分享链接
- 可设置访问密码
- 可设置有效期
- 可限制访问次数
```

```
US-005: 访问分享的笔记
作为一名访客
我想要通过分享链接查看笔记
以便于获取分享的内容

验收标准:
- 链接有效期内可正常访问
- 有密码时需要输入密码
- 显示笔记标题和内容
- 无法编辑（只读模式）
```

### 3.3 AI 能力

```
US-006: AI 智能问答
作为一名用户
我想要向 AI 提问关于我的笔记
以便于快速获取相关信息

验收标准:
- 支持自然语言提问
- 回答基于用户笔记内容
- 显示引用来源（笔记标题）
- 回答准确，无幻觉
```

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 目标值 |
|------|--------|
| 页面加载时间 | < 2s |
| API 响应时间 (P95) | < 200ms (非 AI 接口) |
| AI 检索响应时间 | < 5s |
| 并发用户数 | 100+ (单机部署) |
| 笔记列表加载 | < 500ms |

### 4.2 安全要求

| 要求 | 描述 |
|------|------|
| 认证机制 | JWT Token，支持刷新 |
| 密码存储 | bcrypt 哈希加密 |
| 分享密码 | 单向哈希存储 |
| SQL 注入 | ORM 参数化查询防护 |
| XSS 防护 | 前端输入过滤和转义 |
| CORS | 限制允许的源 |

### 4.3 可用性要求

| 要求 | 描述 |
|------|------|
| 浏览器兼容 | Chrome 90+, Firefox 88+, Safari 14+, Edge 90+ |
| 响应式设计 | 支持桌面端和移动端 |
| 错误提示 | 友好的错误信息和引导 |
| 操作反馈 | 加载状态、成功/失败提示 |

### 4.4 部署要求

| 要求 | 描述 |
|------|------|
| 部署方式 | Docker Compose / 直接部署 |
| 端口 | Nginx: 80, Backend: 8000 |
| 数据库 | PostgreSQL 15+ |
| 外部依赖 | 可选: OpenAI API / 其他 LLM API |
